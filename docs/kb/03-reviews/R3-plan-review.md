## 1. Verdict in one paragraph

The plan is unusually strong for a two-week student build. It is engine-first, contract-first and honest by construction. It has a real cut order, a protected never-cut list and a Plan B in which the report never depends on the UI. The PIT design is sound, with defence in depth and an explicit list of what the code cannot guarantee. **It is not yet internally consistent where it matters most.**

- There is still a back door through which AAPL's survivor-biased drift can set the headline: calibrator centring (RT-01). It also inflates every "skill vs CAPM" grade.
- The CAPM anchor's moment is undefined (RT-04).
- The holdout leaks at long horizons (RT-03).
- The freeze → final → reveal sequence is described four different ways (RT-02).
- A binding unit test is factually wrong (RT-05).
- Shared, append-only state does not survive parallel git worktrees (RT-06).

All of these are cheap to fix on paper today or on D1. The capacity model is optimistic enough that the evidence engine, not only the UI, is at risk (RT-07). **Sign-off: Ready with fixes** (§7).

## 4. The three questions R2 handed to R3 (R2 §8)

   - Nothing resolves ledger keys into the draft (RT-16).

   PB-0 (RT-08) closes the "engine slips past Sat 21" hole.
3. **Can `hist_drift` still set the headline?** **Yes, through calibrator and baseline centring (RT-01)**, and in effect also through an anchor fixed on the wrong moment (RT-04).
